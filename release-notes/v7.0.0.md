# Changelog

### Breaking Changes 🚨

- `3eff179` Define the energy storage entities of the Vitocharge Evolution 08 and treat it as a tested device: inverter active and reactive power, usable battery energy, the battery operation state, grid current, power, and reactive power per phase, the PV status, PV string readings named after their string, and the battery charge and discharge and PV production of the day and year. The battery control mode becomes a defined select with translated options, so its options change from API values such as `powerControlMode` to keys such as `power_control_mode`; update automations and scripts that select one of its options. ([#290](https://github.com/ignazhabibi/vi_climate_devices/pull/290))

### New Features 💫

- `2fad5f3` Define the entities of the Vitoair FS 300E and treat it as a tested device: outdoor, extract, and exhaust air temperature and humidity, supply and extract air volume flow, heat recovery, bypass position and mode, the exhaust fan, the heat exchanger frost protection, and the temporary shutdown quick mode with its runtime. ([#292](https://github.com/ignazhabibi/vi_climate_devices/pull/292))
- `1fb3547` Define the entities of the Vitocal 300-G with the CU401B controller and treat it as a tested device: compressor modulation, overheat, and load class hours, main ECU and heating rod runtimes, primary pump speed, DHW charging, active cooling, and the second DHW target temperature. ([#289](https://github.com/ignazhabibi/vi_climate_devices/pull/289))
- `f900db4` Define the entities of the Vitopure 350 and treat it as a tested device: PM1, PM2.5, PM4, and PM10, supply air temperature and humidity, the air quality and VOC indices, the supply fan, the filter, and the filter change. The ventilation quick mode switches and their runtimes are enabled by default for new entities. ([#288](https://github.com/ignazhabibi/vi_climate_devices/pull/288))
- `ce3dcdb` Define the boiler target temperature of the Vitodens 300-W and treat it as a tested device. ([#287](https://github.com/ignazhabibi/vi_climate_devices/pull/287))
- `ffd7a14` Define the circulation pump options and the cylinder frost protection of the Vitocal 262-A and treat it as a tested device. ([#286](https://github.com/ignazhabibi/vi_climate_devices/pull/286))

### Other Changes ☀️

- `ce3dcdb` Stop creating auto-discovered entities for identifiers, static installation details, and values that the climate, water heater, or fan entity already shows, on every device; the following curation pull requests extend this. Entities that are no longer created remain as orphaned registry entries that can be removed in the entity settings. ([#287](https://github.com/ignazhabibi/vi_climate_devices/pull/287))
- `a33fd51` Report the ventilation reason as a translated state, name the CU401B compressor load compressor modulation, and explain a rejected quick mode start with a quick mode that may already be active. ([#291](https://github.com/ignazhabibi/vi_climate_devices/pull/291))
- `33cde69` Update `vi_api_client` to 7.2.0. ([#267](https://github.com/ignazhabibi/vi_climate_devices/pull/267))

### Bug Fixes 🐞

- `77955ff` Report the ventilation level on devices without a fan entity, such as the Vitocal 300-G and 200-S with an attached ventilation unit. ([#293](https://github.com/ignazhabibi/vi_climate_devices/pull/293))
