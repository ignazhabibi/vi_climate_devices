# Changelog

### Breaking Changes 🚨

- `86f7500` Add a fan entity for ventilation devices such as the Vitoair FS 300E, Vitopure 350, and Vitovent 300-F. The operating modes become translated presets, the fixed level becomes the speed, and standby becomes off, where the device reports these controls. The fan replaces the auto-discovered ventilation mode select, which is removed automatically; update automations, scripts and dashboards that use the select to set the fan's preset mode instead. ([#277](https://github.com/ignazhabibi/vi_climate_devices/pull/277))

### New Features 💫

- `756e033` Define battery, grid, and PV sensors for energy storage systems such as the Vitocharge 03 and Vitocharge Evolution 08: state of charge, battery power and ambient temperature, grid power, PV power, and lifetime totals of battery charge and discharge, grid import and export, and PV production for the energy dashboard. ([#276](https://github.com/ignazhabibi/vi_climate_devices/pull/276))
- `a1fef98` Define the top, middle, and bottom temperatures of the domestic hot water cylinder, the anode current of its corrosion protection, and the minimum comfort temperature, for example on the Vitocal 262-A. The entities read the `dhwCylinder` and `dhw.configuration` successors of the deprecated features and fall back to the deprecated features. ([#275](https://github.com/ignazhabibi/vi_climate_devices/pull/275))
- `395c566` Define the coefficients of performance and the refrigerant discharge pressure of legacy heat pumps with the CU401B controller (Vitocal 200-S, 300-G, 333-G). Their second copies of the suction pressure and the hot, liquid, and suction gas temperatures no longer create auto-discovered sensors, because the defined compressor and evaporator sensors report the same values. ([#274](https://github.com/ignazhabibi/vi_climate_devices/pull/274))
- `8702eb6` Define the daily and yearly gas consumption of heating and domestic hot water, a burner binary sensor, and the hydraulic separator temperature for gas boilers. The other gas consumption periods and the raw history arrays no longer create auto-discovered sensors, like the power consumption summaries. ([#273](https://github.com/ignazhabibi/vi_climate_devices/pull/273))
- `5dceb9d` Read the outside temperature of system controllers such as the Vitocal 200-A from `system.temperature.outside`. ([#272](https://github.com/ignazhabibi/vi_climate_devices/pull/272))
- `6747e3c` Treat the Vitocal 250-A model `E3_Vitocal_17` as a tested device, so its auto-discovered entities are disabled by default, and define the DHW hygiene temperature as a number entity. ([#269](https://github.com/ignazhabibi/vi_climate_devices/pull/269))

### Other Changes ☀️

- `d450ce5` Skip sensor connection statuses such as `connected` next to a reading in the auto-discovery; real states such as `heating.dhw.status` are kept. Auto-discovered sensors that are no longer created remain as orphaned registry entries that can be removed in the entity settings. ([#271](https://github.com/ignazhabibi/vi_climate_devices/pull/271))
- `3cd61c3` Map more API units of auto-discovered sensors to Home Assistant units and device classes: gas volume, air volume flow, particulate matter, fan speed, temperature differences, voltage, milliampere, distance, and durations. Where such sensors already record unitless long-term statistics, Home Assistant may ask to fix the statistics unit. ([#270](https://github.com/ignazhabibi/vi_climate_devices/pull/270))
